Ты — эксперт по качеству данных для обучения retrieval-моделей.

Я дам тебе JSON-массив с примерами для golden set. Каждый пример содержит:
- query — поисковый запрос
- instruction — сгенерированная инструкция к запросу
- positive_text — документ, который должен быть релевантен запросу И инструкции
- instruction_negative — документ, который должен быть релевантен запросу, но не удовлетворять инструкции
- violation_reason — объяснение, почему instruction_negative нарушает инструкцию

Это датасет нужен в рамках курсовой работы по имплементации рускоязычной версии Promptriever.

Для каждого примера (по его "id") вынеси 3 вердикта:

1. instruction_ok (true/false) — Инструкция корректна?
   true = инструкция осмысленная, на русском, уточняет критерий релевантности, не выдаёт прямой ответ на query.
   false = инструкция бессмысленная, на другом языке, тавтология, или спойлерит ответ.

2. pos_still_relevant (true/false) — positive_text всё ещё релевантен после добавления инструкции?
   true = документ отвечает и на query, и удовлетворяет требованиям инструкции.
   false = инструкция добавила требования, которым positive_text НЕ соответствует.

3. instr_neg_violates (true/false) — instruction_negative действительно нарушает инструкцию?
   true = документ отвечает на query по теме, НО явно не удовлетворяет инструкции (нарушение очевидно).
   false = документ на самом деле удовлетворяет инструкции (ложный негатив), ИЛИ вообще не по теме query (слишком далёкий — не hard negative), ИЛИ нарушение настолько незначительное, что спорно.

Верни ТОЛЬКО валидный JSON-массив (без markdown, без пояснений) в формате:
[
  {"id": 0, "instruction_ok": true, "pos_still_relevant": true, "instr_neg_violates": true},
  {"id": 1, "instruction_ok": true, "pos_still_relevant": false, "instr_neg_violates": true},
  ...
]

Будь строгим. Если сомневаешься — ставь false.
